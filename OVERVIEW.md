# Paseo Team (Paseo Bot plugin)

Paseo Bot is your assistant for understanding goals and organizing Agents to carry them forward on one connected daemon host. Discuss ideas and develop shared understanding using current findings from relevant project Agents, then coordinate concrete work when requested. For a new matter Bot uses a fresh project Agent, continuing an existing Agent when it already carries relevant groundwork for that same matter. Bot distinguishes confirmed facts from assumptions and open questions. Consultation alone does not authorize project changes. Bot remains responsible for coordination after delegation; project Agents own execution. Applicable specialist skills and workflow tools handle task-specific dispatch and associations; generic Paseo delegation is the fallback when no specialist workflow applies.

Each goal conversation is a normal durable Paseo Agent in the dedicated background Bot workspace. The Paseo Team sidebar entry opens that native workspace directly, including first use: there is no setup page or intermediate open button. Create conversations, choose runtime settings and manage drafts through the native UI. Opening the entry creates no empty Agent and does not create or modify presets. Without a saved dedicated Coordinator association, new conversations use valid native settings and the [public default coordination rules](docs/paseo-team-spec.md#默认通用规则).

If a dedicated Coordinator preset was previously configured, its association remains active. For that dedicated preset only, the plugin treats “When to use” notes as instructions for new Coordinator conversations. Other presets retain Paseo's normal usage-notes meaning. Notes are visible through `list_profiles`; do not put credentials there. Edit runtime fields and notes through Settings → Agent profiles. New sessions load the dedicated settings and notes through the public creation hook; blank notes mean no additional rules. Existing sessions keep their saved configuration and instructions. The public plugin API cannot preselect a profile in the native composer: mismatched providers or permission modes stop creation with a selection hint, rather than silently changing permissions. The legacy creation RPC uses the same resolver and requires an explicit model in the dedicated preset.

Native chat continues to own the first send, drafts, streamed Markdown, tools, permission requests, questions, Stop and later configuration changes. Use native new-tab controls for another goal conversation and Bot history in the workspace header for the existing history list.

## Setup and compatibility

Requires Paseo **0.13.2 or later**, with the Paseo CLI available on the daemon's PATH. Newer releases, including beta versions, are allowed to load. Runtime acceptance was performed on 0.13.2; newer releases may introduce API changes and have not all been tested. Paseo owns the native picker and preferences, while the dedicated preset supplies explicitly set fields for new Team conversations; existing conversations retain their own configuration. Codex is the real Provider exercised by the acceptance record. Other Providers depend on their public Paseo adapters and have not been independently accepted.

Management capabilities depend on the selected Provider's available Paseo tools and the daemon's MCP injection/tool policy. In 0.13.2, `daemon.mcp.injectIntoAgents` defaults to false; a host administrator must explicitly configure supported MCP injection and permitted tools when management is desired. The plugin does not enable disabled tools or bypass normal permissions. Its only host configuration write is the user-requested initial addition to Agent profiles through public `config.get/patch`. If management tools are unavailable, the Bot should explain the missing capability. Review your existing Paseo MCP settings when you intend to allow management; injection is not enabled by this plugin.

Desktop and compact mobile browsers are the release target. Drafts and preferences now use native chat storage. Native iOS/Android apps and Electron are untested. See the repository's compatibility and verification records for the actual acceptance evidence.

## Conversations and delegated work

The plugin no longer provides an initial configuration form or first-message editor. All chat creation, drafts, model selection, sending, reconnect handling and message actions belong to Paseo. Old Bot-local drafts and preferences are not migrated or read.

Bot History retains previously registered conversations and includes non-internal root Agents in the dedicated workspace generations opened through the native Bot entrance. It excludes delegated children and business workspace sessions. It reads the daemon each time, including after a plugin restart, without copying transcripts or requiring an agent-created notification to arrive.

Rename conversations, archive them after execution is confirmed stopped, and open archived history using the host’s native behavior. Archiving the Bot workspace requires an explicit manual rebuild before further Bot work. Rebuild creates a new workspace identity while preserving old history and shared files.

Management stays on the current host and requires actual targets. The default rules ask the Coordinator to report unclear targets and respect project workflows; available Paseo tools support visible business workspaces and ordinary parent/child completion notifications. Delegation and completion appear in the native conversation and its normal navigation. Delegated Agents do not appear in Bot History. These instructions do not replace Provider permissions or guarantee enforcement by every external tool transport.

## Data and permissions

The daemon's ordinary `PASEO_HOME/bot` directory, normally `~/.paseo/bot`, holds shared task files. It is separate from the installed plugin source. All Bot conversations on that host share files; the directory is not a filesystem sandbox and concurrent edits can conflict. Paseo stores durable transcripts. Plugin data stores the dedicated preset ID and initialization outcome, workspace generations, owned conversation references and delivery fingerprints; it does not maintain a second transcript. Legacy delivery metadata is retained for compatibility; new native sessions use the host’s own storage and delivery behavior.

Conversation prompts, tool inputs/results and files accessed by authorized tools can be sent to the selected external Provider under its own data policy. Local history does not imply that conversation data stays on the daemon. This is a trusted plugin running with the daemon user's privileges. Stop and rename use the supported local CLI with the exact selected daemon home; archived-workspace inspection uses a read-only public SDK helper and local daemon authentication without exposing credentials. The plugin does not download software at runtime.

New sessions in the dedicated Bot directory load the current dedicated preset notes once, preserving other creation instructions and valid runtime settings. Native and legacy creation both use the same resolver. Ordinary project directories do not receive Coordinator rules. The public creation hook has no workspace/parent identity, so the Bot directory must remain dedicated to coordination rather than project execution; guidance does not grant history ownership or filesystem isolation.

Preset setup uses a persisted stable ID, serialized plugin operations, a fresh read before adding the profile, and read-back confirmation. Public patches replace the full profiles array and provide no cross-client compare-and-swap: simultaneous edits from another client can be lost. Avoid editing presets from another client during setup. Subsequent entry, upgrade and reload do not refill the preset. A confirmed missing dedicated preset uses the native configuration (explicit input for legacy RPC) with the public default rules; it is not automatically recreated. Configuration read errors are reported rather than treated as deletion. See the [confirmed specification](docs/paseo-team-spec.md) and [lifecycle acceptance](docs/verification/issue-16.md).

When setup acknowledgement is lost, the plugin reads the stable ID back and keeps any edits already made there. A still-unconfirmed attempt is not submitted again. Explicit permission denial can be retried after access is restored. Missing/corrupt plugin state or a lost association is reported separately from a successfully confirmed missing preset. Surviving reserved preset IDs or the dedicated directory workspace are only evidence of possible lost state; they are never adopted by name. Restore verified plugin data to recover its association. Complete removal of both metadata and observable traces cannot be distinguished reliably from first use.

New conversations validate the resolved Provider/model/mode/thinking against the public Provider catalog. Missing optional native fields retain host semantics; the legacy SDK path still requires an explicit valid model and its existing thinking choice. Configuration errors do not activate the deletion fallback. Reload, restart, a changed default seed, and reinstall do not refill user notes; old sessions retain saved instructions. Removing the plugin does not delete its host preset or durable conversations.
