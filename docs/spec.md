# Paseo Bot：单主机管理助手插件规格

状态：完整插件已实现并完成浏览器、隔离 daemon 与真实 Provider 验收；Git v0.1.0 已发布。官方目录申请 getpaseo/plugins#1246 已通过社区允许的手工 PR getpaseo/plugins#1250 提交，等待独立审核，尚未上架。完整要求和已确认的平台范围不变。

## Problem Statement

用户需要一个稳定的对话入口来查询、管理和调度当前主机上的 Paseo 工作，并处理不归属具体业务项目的任务。把入口放进某个业务 Agent 会让管理对话与业务上下文混在一起；每次切换项目也不应切换管理助手身份。

## Solution

提供独立 Paseo 插件页面，通过全局侧栏进入。页面自身顶部工具栏放置“新对话（＋）”与“历史记录”按钮；宽布局历史下拉，紧凑布局使用可触摸的选择面板。每个主机复用专用后台工作区，以 daemon 用户的 `~/.paseo/bot/` 为普通工作目录，每个 Bot 对话是独立 Agent session。

用户无需手动创建项目；daemon 自动建立正常项目/工作区归属。该方案接受底层工作区模型，不实现无工作区 Agent。源码仓库和 runtime 工作目录分离。首期仅管理 Bot 所在主机，不因为全局页面增加权限或跨主机访问。

## User Stories

1. 作为用户，我希望从全局侧栏打开 Bot 页面，无需先选择业务工作区，以便随时管理本机工作。
2. 作为用户，我希望在 daemon 的专用普通目录运行 Bot，以避免将管理会话放进业务仓库。
3. 作为用户，我希望复用一个后台 Bot 工作区，以隐藏日常侧栏中的管理资源并保留正常持久化。
4. 作为用户，我希望打开空白新对话但首次发送才创建 Agent，以避免误点产生空会话。
5. 作为用户，我希望选择 Provider、模型、思考强度与权限模式，以匹配本次任务。
6. 作为用户，我希望首次明确选择配置并在后续新对话复用上次选择，以减少重复输入。
7. 作为用户，我希望已有对话保留自己的配置，以避免新对话配置改变旧会话。
8. 作为用户，我希望默认不跳过审批，以保留实际执行所需的确认。
9. 作为用户，我希望读取流式文字和 Markdown，以跟踪回答。
10. 作为用户，我希望查看工具调用状态、结果与错误，以判断实际进展。
11. 作为用户，我希望在对话内处理权限请求和 Provider 提问，以继续被阻塞的执行。
12. 作为用户，我希望停止当前对话执行，以改变方向而不影响其他会话。
13. 作为用户，我希望运行中编辑草稿但等待结束或停止后再发送，以避免队列和引导语义不一致。
14. 作为用户，我希望用页面工具栏的加号开始新对话，以保持上下文独立。
15. 作为用户，我希望从历史菜单查看按最近活动排序的未归档 Bot 对话，以快速返回工作。
16. 作为用户，我希望在历史中看到运行与待确认状态，以找到需要关注的会话。
17. 作为用户，我希望重命名对话，以识别不同工作。
18. 作为用户，我希望多个对话并发执行且切换或离开页面不停止，以同时跟踪不同任务。
19. 作为用户，我希望各对话分别保留草稿，另有一份新对话草稿，以避免导航丢失输入。
20. 作为用户，我希望草稿按设备、主机与会话隔离且发送成功才清空，以保留本地编辑。
21. 作为用户，我希望各设备分别恢复每个主机最后选择的对话，以避免手机导航改变电脑显示。
22. 作为用户，我希望失效的记忆选择回到空白草稿页，以避免打开错误会话。
23. 作为用户，我希望停止运行中的会话后归档，以明确控制执行结束。
24. 作为用户，我希望查看只读的已归档对话，以保留历史证据。
25. 作为用户，我希望需要继续旧工作时新建对话并自行提供上下文，以避免隐式恢复或复制。
26. 作为用户，我希望不永久删除或自动清理历史，以保留已有记录。
27. 作为用户，我希望多个 Bot 对话共享文件但不共享聊天上下文，以在同一目录处理任务。
28. 作为用户，我希望发送失败或 Provider 不可用时保留输入并显示可操作错误，以便修正重试。
29. 作为用户，我希望发送结果不明时先核对历史与运行状态，以避免重复执行有副作用的任务。
30. 作为用户，我希望断线重连后补齐历史和状态，以继续观察原任务。
31. 作为用户，我希望Bot 工作区被归档后自行决定是否重新创建，以尊重已有归档动作。
32. 作为用户，我希望重建工作区后仍能查看旧会话历史，以避免历史被替换或遗失。
33. 作为用户，我希望查询 Agent 和工作区状态并汇总进展，以通过自然语言管理当前主机。
34. 作为用户，我希望向指定 Agent 派发或追加任务，并创建普通可见的业务工作区，以承接实现工作。
35. 作为用户，我希望查询和管理现有定时任务，以复用 Paseo 调度能力。
36. 作为用户，我希望使用已授权工具处理明确交办的普通任务，以兼顾管理和实际操作。
37. 作为用户，我希望从 Bot 回答打开委派目标，以检查业务工作区里的执行结果。
38. 作为用户，我希望Bot 历史只显示 Bot 页面创建的对话，以免混入委派 Agent 和其他会话。
39. 作为用户，我希望目标含糊时得到澄清，以避免依据当前浏览页面猜测目标。
40. 作为用户，我希望在桌面和紧凑布局通过触摸、键盘及辅助标签完成交互，以跨设备使用。

41. 作为社区用户，我希望从公开 GitHub 源安装经过验收的固定版本，并在 Paseo 官方插件目录发现它，以复用该插件。

## Implementation Decisions

以下决策17是2026-10-27用户确认的最新架构，覆盖早期自绘聊天页、运行中禁发、已有会话草稿、归档只读以及专用工具栏始终驻留等冲突约束；其余身份、单主机、安全和历史保留要求继续适用。

1. **插件边界。** 使用受支持的公开插件 SDK，入口与界面归 client，目录创建、安装实例身份和持久元数据归 server，RPC 契约归 shared。遵循运行时导入边界，不导入宿主私有聊天模块。宿主标准 UI 提供主题、Markdown、流式文字等基础组件；完整消息、工具、权限与提问交互由插件组合。
2. **身份与持久化。** 记录每个主机的 Bot 工作区及通过 Bot 页面创建的会话身份；目录名和 cwd 不单独作为所有权凭证。可靠复用工作区，避免重复点击、多个客户端或并发首次发送生成重复工作区/会话。会话转录只由 Paseo 保存；插件元数据保留旧工作区世代和会话引用，以供重建后浏览旧历史。客户端输入不能越过对应 host/安装实例的操作范围。
3. **首次发送。** 新建页只是草稿，首次发送才创建 Agent。验证公开 Provider 目录中的可用模型、思考选项和模式，记住新对话选择；不支持的选项不伪造。首次明确选择，不默认绕过审批。旧对话继续使用其配置。
4. **创建配置偏好。** 在当前设备按 host 记住上次新对话选择，作为首期的偏好存储边界；不会修改旧会话或覆盖其他设备的选择。可用性发生变化时说明错误并允许重选。
5. **历史与选择。** 按最近活动排序，包含所有未归档 Bot 会话，正确分页；显示标题、运行/待确认等实际状态，支持重命名、归档和查看已归档会话。只有 Bot 页面创建的会话进入此列表，委派 Agent 不进入。每台设备记住每个 host 最后选中会话；失效选择回到空白页，不打开同名替代资源。自动初始标题可取首条消息的简短摘要，不引入额外模型调用。
6. **草稿。** 当前设备按 host、会话和新对话槽位保存未发送文字。切换、点击加号、刷新或关闭页面保留；确认接收成功后只清理本次提交的草稿版本，保留提交期间新增编辑。草稿不跨设备同步。
7. **运行。** 会话可并发，切换或离开仅释放界面观察，不停止任务。当前 turn 运行时允许编辑但禁止发送；无队列和 steer。Stop 只停止当前会话，显示 pending/成功/失败，未明确停止前不允许归档；不使用 archive 假充停止。
8. **交互。** 文字/Markdown、实时增量、工具状态/结果、权限请求、Provider 提问和 Stop 均属于首期。提供明确的加载、离线、错误、空状态与重试，保护焦点、键盘、安全区和滚动。选项回答和权限请求必须绑定准确会话和请求；不以提示词替代执行权限，不笼统自动批准工具。
9. **重连与不明结果。** SDK 实时订阅需配合初始历史、分页和断线后的补读及 epoch 变化。先核对实际历史/执行状态再允许重试，防止首条创建和后续发送被重复执行。无确定证据时明确展示未知状态，不伪装失败或自动重做。释放订阅并屏蔽切换后的迟到响应。
10. **归档。** 已归档会话只读，无取消归档、永久删除、自动复制上下文或自动清理。Bot 工作区被外部归档时显示原因，仅在用户点击重建后创建替代；旧世代历史保留可见。原记录失效与暂时断线区分，不因超时重建。
11. **共享目录。** 所有对话共享工作目录文件，无对话间 filesystem isolation。并发同文件修改不自动隔离。目录不是权限沙箱，不扫描或回显 daemon 其他私有配置与凭据。
12. **管理。** 通过现有 Paseo 工具与授权处理查询、汇总、发消息、创建业务工作区、定时任务和明确交办的普通任务。只面向当前 host；不使用当前浏览页面推断目标。业务工作区正常可见，避免继承 Bot 的 background 标记；委派保留正常 parent/child 生命周期，UI 提供真实目标导航。
13. **兼容性验证。** 在实际安装的 daemon、app 和公开 SDK 上确认最低版本与接口。当前参考源码的 Agent handle 未暴露独立 Stop、rename 或统一 Provider 提问方法，不能据此声称完整接口已就绪。先验证公开 CLI/SDK 是否覆盖；存在可行公开路径时用最小实现接入，缺失则以证据报告阻塞和必要宿主扩展，不私用内部接口、不静默省略首期功能、不修改 Paseo 核心以掩盖缺口。声明真实 semver 范围，后台工作区按 feature gate 使用。

14. **社区发布。** 首期采用公开 GitHub Git 源发布，不为交付强制增加 npm 发布链。最终任务提供实际 manifest/entry/依赖锁、最低兼容版本、公开许可证和第三方归属、英文 listing、真实脱敏界面截图、数据流与权限披露，以及固定发布修订的隔离安装证据。按官方模板向 getpaseo/plugins 提交带 submission 标签的申请，跟踪 review PR 并修复具体问题；“已申请”“审核中”“已上架”分别记录，外部审核通过后才能宣称已上架。发布前重新核对当前官方文档与政策。用户随后明确要求按社区规范提交 PR；当前 BOTS.md 允许手工 PR，因此标签权限阻塞时采用关联原申请的手工记录 PR。

15. **首发平台保证（2026-10-27 用户确认）。** 兼容目标为最新稳定版，当前基线为 Paseo app/daemon/SDK 0.13.2；首发以桌面和手机浏览器实际验收为准。用户确认暂不保证 iOS/Android 原生端的完整功能：0.13.2 全局插件页面尚无受支持的原生设备本地持久存储接口，偏好、草稿和最后选择的原生恢复能力应明确标为不支持，不用 daemon 共享存储替代、不私用宿主模块。浏览器端仍须实现全部既定行为。Electron 和原生设备未实际验证的项目继续单列，不据浏览器结果宣称通过。发布前复核最新稳定版本及实际兼容证据。

16. **原生对话界面对齐（2026-10-27 用户确认）。** Bot 对话界面应基本还原 Paseo 原生对话界面的消息排版、内容宽度、间距、输入区、发送/停止控件、工具结果与权限/提问卡片、滚动及紧凑布局。复用公开主题和基础 UI 组件组合实现，以同版原生对话界面作视觉和交互对照；不导入私有聊天模块。保留 Bot 页自身的新建/历史工具栏及已有首期功能边界。

17. **直接使用原生对话（2026-10-27 用户确认）。** Bot 全局页面只负责入口、新建会话的首次配置/首发、Bot 历史、rename/archive 与工作区状态/手动重建。成功首发或选择已有会话后，使用公开 `navigation.openAgent({agentId, serverId})` 打开同一 Agent 的原生对话页；不嵌入或仿制私有聊天组件。后续消息、模型/思考/权限修改、运行中发送策略、工具组与详情、权限/Provider 提问、Stop、消息操作、草稿、滚动和归档后的行为均由原生页面负责，不再声称插件强制“运行中禁发/归档只读”。Bot 入口保留首发草稿和不明投递恢复，不因重连或导航错误重复发送。回到 Bot 入口不自动跳回旧会话。历史只能打开本 host 已登记的 Bot，会话/历史/文件保留。旧版保存在 Bot 浏览器存储中的会话草稿和待核对投递必须有可操作的恢复入口，不能静默丢弃；与原生草稿不自动合并或覆盖。若宿主缺少公开导航接口，显示明确错误并禁止首发，不创建无法导航的会话。用户此次授权验证后更新本机插件；不重启生产 daemon。

## Testing Decisions

用户已确认以“插件页面 → 真实隔离 daemon → 现有 Provider 适配”为主要验收接缝。复用 Paseo 已有隔离 daemon harness、插件 runtime/import boundary 测试和浏览器交互模式；独立仓库仅补最小可运行接入，不复制整套宿主框架。

- 每项 ticket 是可演示的纵向切片，包含所需客户端、服务端、契约和测试。遵循一项行为一个 red-green 周期；只在高层难以定位时补小范围纯逻辑测试。
- 浏览器桌面/手机宽度覆盖导航、输入、历史、新建、rename、归档、键盘/触摸、等待和失败；手机宽度浏览器不等于 iOS/Android 原生验收。
- 使用真实临时文件系统、隔离 daemon 和测试插件验证目录/工作区复用、会话身份、历史分页、读写归属、并发创建和重建后旧历史。避免真实生产配置和用户资源。
- 确定性场景可使用现有可控 Provider 适配以触发流式、工具、权限、提问、停止、断线、迟到响应和不明发送；fixture 成功不替代实际模型验证。
- 在可用的真实配置 Provider 上至少完成一条真实文字→工具→需确认→继续→停止/完成的验证链；记录实际支持边界和缺失接口。不得新增 auth 检查或要求用户为测试重配认证。
- 两个浏览器客户端验证共享历史但选择/草稿各自独立；切换会话/host 后迟到事件不能串数据。首次创建和发送不明后不重复执行，归档旧世代历史仍可读。
- 验证单主机查询、明确目标委派、普通可见业务工作区、定时任务与目标跳转，使用隔离资源，禁止为了验收操作真实生产任务。
- 引入代码时提供类型、lint、格式和针对性测试 npm scripts，记录实际命令、退出码、代码 SHA、app/daemon/SDK/Provider 版本、截图/录屏和未测平台。只跑相关测试，禁止本地跑完整 Paseo monorepo 测试。
- iOS、Android 和 Electron 的受影响行为按可用设备验证，无法执行明确记为未测，不宣称跨平台已验收。兼容性与生产安装另设实际证据，不以源码检查代替。

## Out of Scope

悬浮圈/悬浮窗、系统快捷键、真正无工作区 Agent、跨主机调度、共享记忆平台、新权限体系、每会话文件隔离、图片/文件附件、语音、全文对话搜索、运行中发送/队列/steer、取消归档、永久删除、自动复制上下文及历史清理。本轮初始化交付建立公开仓库、规格、任务和实施工作区/Agent；后续任务的最终交付包含 Git 发布与社区目录申请及审核跟进。生产插件安装、生产配置变更和生产 daemon 重启仍不在授权范围。
